## 第3页：一、待解决的问题 · 行业痛点

**核心内容**：
- 聚焦**中小机械加工厂金属零件多品种小批量离线抽检**场景，三大核心痛点：
  1. **换产成本高**：新零件质检需标注缺陷、训练模型，周期长、成本高，小批量产线难以承担
  2. **分析效率低**：翻标准、写报告、分析根因高度依赖人工经验，单份报告耗时 30 分钟以上
  3. **合规性弱**：人工判定标准不统一，结论无溯源记录，不符合质检可追溯要求
- 现有方案：纯检测工具功能单一；纯大模型方案幻觉不可控；定制系统成本高，中小工厂难以复用

**答辩提示**：从真实业务痛点切入，不讲空泛的"工业4.0"，聚焦中小工厂换产快、人员不足的真实问题。

## 第4页：一、待解决的问题 · 系统定位与目标

- **系统定位**：人在回路的离线质检辅助工具，**不替代人工最终判定**，AI 负责定位、初筛、整理依据，人工负责最终确认
- **核心目标**：
  1. 少样本条件下完成缺陷检测定位，换产无需模型训练
  2. 自动匹配标准、生成分析报告，降低质检人工工作量
  3. 所有结论可溯源、可校验，符合质检合规要求
- **应用场景**：金属零件表面缺陷离线抽检、新产线快速质检搭建、质检新人培训辅助

**答辩提示**：主动讲清系统边界，不吹"全自动替代人工"，定位清晰准确。

## 第5页：二、研究现状与调研分析

- **工业缺陷检测两条技术路线**
  1. 监督学习路线（YOLO、CNN）：精度高，但需大量标注，换产成本高，少样本场景适配差
  2. 零样本异常检测路线（WinCLIP 等）：仅需正常样本建库，适配小批量换产场景，但缺少分析能力
- **大模型与 RAG 的工业应用**
  生成式 VLM、RAG 开始应用于文档问答、故障分析，但多为纯文本方案，缺少与视觉检测的深度融合；且幻觉不可控，不符合合规要求
- **现有方案共性不足**：要么只有检测没有分析，要么只有分析没有定位；缺少兼顾效率、精度、合规性的完整工作流方案

## 第6页：三、系统架构 · 双链路门控核心机制

- **整体分层**：数据输入层 → 感知检测层 → 门控路由层 → 双链路执行层 → 应用交互层；底层为知识库底座
- **核心机制：置信度门控双链路**
  1. **感知层统一计算**：输入图像 → WinCLIP 计算像素级异常分数 → 生成全局异常置信度
  2. **门控路由**：
     - 高置信（异常分数 ≥ 阈值）：走**快链路**，直接输出缺陷位置、异常等级、热力图，不触发 VLM 分析
     - 低置信（异常分数 ＜ 阈值）：走**慢链路**，裁剪缺陷区域 → VLM 生成描述 → RAG 匹配标准 → 输出完整分析报告
  3. **反馈链路（三级反哺）**：
     - 一级：人工复核结果存入**历史案例库**，不直接修改标准
     - 二级：定期根据案例数据**辅助调整异常分数阈值**，优化门控准确率
     - 三级：标准库更新需人工审核后发布，避免知识库污染
- **阈值确定方法**：基于验证集异常分数的**中位数 + 1.5×MAD**作为初始阈值，后续支持人工微调
- **漏检兜底**：高置信快链路输出结果仍需人工抽检，低置信慢链路全量人工复核

**答辩提示**：放一张高置信/低置信样例并排对比截图，视觉冲击力远超文字。

## 第7页：三、系统架构 · 四层一底座详情

- **感知检测层**：WinCLIP 正常特征记忆库、多尺度滑窗检测、异常热力图生成、缺陷区域裁剪
- **认知分析层**：VLM 缺陷描述生成、RAG 标准检索与页码溯源、根因推理、结构化报告生成
- **门控路由层**：置信度计算、阈值判断、链路调度、结果冲突处理
- **应用交互层**：单图检测、批量处理、报告导出、知识库管理、历史记录
- **知识库底座**：正常特征库、质检标准库、历史案例库、报告模板库

## 第8页：三、核心机制 · 页码级可溯源校验

- **目标**：解决 VLM 编造引用、引用错误的问题，满足工业质检合规要求
- **具体实现机制**：
  1. 知识库预处理：每个标准片段分配唯一**引用 ID**，绑定原文内容、页码、标准号
  2. RAG 检索：返回结果同时包含「片段内容 + 引用 ID + 页码 + 标准号」
  3. VLM 生成约束：Prompt 强制要求必须携带引用 ID，不允许无引用生成结论
  4. **后处理一致性校验**：自动检查输出中所有引用 ID 是否存在于本次检索结果中
     - 校验通过：正常显示，标注对应标准号、页码
     - 校验不通过：自动标红提示「引用待核验」，建议人工复核
- **降级模式**：VLM 输出格式异常时，自动降级为直接展示 RAG 检索到的原始标准片段，由人工选择适用条款
- **设计原则**：不追求零幻觉，追求所有引用可校验、错误可识别

**答辩提示**：现场展示一页真实的标准文档分块截图，标注引用 ID，旁边放 VLM 生成的结论和校验通过标识。

## 第9页：四、项目创新点

1. **应用架构创新：置信度门控的双链路质检架构**
   - 兼顾检测效率与分析深度：高置信快检、低置信精析，避免全量图都走大模型分析的算力浪费
   - 具体实现：异常分数门控 + 快慢双链路路由 + 三级反馈机制
2. **场景工作流创新：少样本全流程质检闭环**
   - 覆盖「建库→检测→定位→分析→报告→迭代」完整质检流程，适配中小批量换产场景
   - 具体实现：仅需 10-20 张正常样本建库，无需标注缺陷；换产适配周期 0.5-1 天
3. **工程实现创新：引用 ID 绑定的可溯源校验机制**
   - 所有判定依据绑定标准原文与页码，输出自动校验引用一致性，符合工业质检合规要求
   - 具体实现：片段 ID 化 + 生成约束 + 后处理一致性校验 + 降级模式
- **统一说明**：底层视觉模型、语言模型、RAG 框架采用开源成熟组件，本项目创新集中在应用架构、工作流设计与工程落地，不做模型层原创。

## 第15页：七、风险预案与总结

- **风险预案**

| 风险 | 应对 |
|---|---|
| WinCLIP 效果不达预期 | 替换 PatchCore/Anomalib，接口兼容 |
| VLM 速度过慢 | 切换轻量化模型，或高频场景模板化生成 |

| 门控阈值不合理 | 中位数+1.5×MAD 辅助标定，支持人工微调 |
| JSON Schema 不服从 | 正则提取中间层；成功率低直接降级人工选 |

## 答辩注意事项

1. 全程突出「应用系统」「工程落地」，少讲算法细节，多讲功能、流程、价值
2. 创新点主动讲清边界，不碰"模型原创"的雷区
3. 先导实验部分重点讲"已经做了什么、验证了什么"，体现执行力
4. 所有结论留有余地，强调"辅助工具、人在回路"，避免被质疑落地性
5. 开场主动说三句话：底层用开源组件、创新在应用层、开题用公开数据集验证架构
