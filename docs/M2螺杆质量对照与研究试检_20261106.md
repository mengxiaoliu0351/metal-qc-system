# M2螺杆质量检测：数据审计、三方案对照与网页试检

更新日期：2026-11-06。候选版本 `m2-body-quality-v1`。本轮结论是扩充螺丝族的质量验证覆盖，不能称为覆盖所有螺丝型号。

## 1. 解决什么问题

前一阶段三类外观匹配回答“这张图适合参考哪类图片”，没有正常／缺陷真值，不能证明质量检测效果。本轮使用有来源质量标签的螺杆数据，单独验证“是否有缺陷”。外观资料审核的24张可用图与72张排除参考均未充当正常件或质量训练标签。

本轮在螺丝族下面增设M2螺杆质量候选。它和已有头部视图、MVTec螺丝研究模型的关系是扩展同一产品族的适用视图；尚未把三个研究入口合并成一个经整体验证的多型号生产模型。不能把相同M2规格的两个拍摄视图说成两个厂家或两个独立产品型号。

## 3. 固定方案如何工作

原图中的螺杆较小。先用不使用质量标签的中央连通区域规则提出裁剪区域，扩大边缘并补边至224像素；找不到候选时使用完整图。三种方案共用相同预处理、冻结CLIP编码器和测试图。没有框真值，不能把候选区域数量称为定位准确率。

1. **正常参考记忆库**：80张正常参考，保留512个代表局部特征，最大余弦差异作为分数。下阈值取100张正常校准图分数的99百分位，不使用缺陷训练标签。
2. **有标签整图判别**：400张训练图，冻结CLIP整图特征，StandardScaler＋Logistic Regression，固定C=0.1。
3. **融合判别**：局部差异分数与整图判别分数输入第二个轻量判别器。训练融合时整图分数来自5折折外预测，避免直接使用该训练图自身拟合所得分数。最终整图头再用全部400张训练图拟合。

另两种方案使用了缺陷标签，和正常库的监督信息预算不同；不能把提升全部归于“统一建库”，也不能称整个增强方案为零样本。选择规则在测试前固定：只按校准集平衡准确率选择，平手优先简单方法。本轮选中 **局部分数＋整图判别融合**，不是事后挑测试最好的一栏。

视图检查比较BODY与HEAD正常参考中心，仅校准适用范围。100张历史HEAD留出图作异视图对照，不参与BODY质量分类训练。它们属于已使用来源的对照，不是新的厂家盲测。若不符合BODY范围，网页不输出正常／缺陷质量结论。

## 5. 发布门槛与网页行为

预先设定：资格检查和最终测试缺陷召回≥90%、正常误报率≤10%、BODY范围通过率≥95%；最终历史HEAD排除率≥95%。这是本项目研究试检门槛，不是行业认证标准。

本轮门槛结果：**未通过，仅展示报告，不启用试检**。原因：封存测试正常件误报率14.60%，超过预设10%上限。

事后诊断（未用于重新拟合）：正常件在校准、资格检查、最终测试的误判分别为1/100、3/100、73/500，分数中位数分别为0.0877、0.0845、0.1867。可见正常分数分布发生变化，当前校准对最终测试覆盖不足；尚不能据此断定具体由光照、背景或零件形态引起。测试中有62张正常件进入候选的高风险区，因此不能直接赋予该候选“高风险自动归档缺陷”的权限。

下一轮优先研究正常参考覆盖、图像区域处理和分数校准的稳定性，并用此前未参与开发的数据检查。当前998张成绩已被查看，之后只能作开发回归，不能反复调参后再次称为新增盲测；本轮失败记录永久保留。

入口：[MetalQC产品接入](https://metalqc.online/#products) → 产品族库 → 螺丝族 → “M2螺杆质量验证 · 来源OK／NG标签”。可查看三方案对照；通过门槛才显示上传和固定样例试检。六张样例按像素哈希确定性选择，非挑选预测正确图片，包含两张正常、两张缺陷和两张HEAD异视图。

本研究接口不调用VLM、不写正式检测历史、不自动归档、不生成反馈训练标签；输出必须核验。原四产品配置、原HEAD自动处置暂停、已有统一库V2和外观匹配V3均保留。不能用此模块的准确率替代完整双链路系统成绩。

## 7. 这一步能与不能说明什么

可以说明：用同一套冻结视觉特征与有来源质量标签的数据，螺丝族可以逐步扩展到新的受控视图；存在不合格／范围不符时应拒绝启用或拒绝判断。正常库与有标签增强必须完整对照，而不是只展示最高准确率。

尚不能说明：三类外观均能检出缺陷、所有型号共库都可靠、跨厂家或实物泛化已解决、复杂多件照片可自动定位、已获得检验员或机构认证。下一步应在此基础上验证统一族入口的自动视图路由，再增加有质量真值的其他结构，保持未覆盖外观拒判。
