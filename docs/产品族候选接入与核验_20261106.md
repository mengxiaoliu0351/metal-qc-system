# 产品族候选接入与核验

## 本阶段解决的问题

先把“用户只选螺丝族，内部统一组织多种外观”的管理基础做实。不同产品族独立保存候选样本、核验记录和模型绑定；新增一个产品族不会套用螺丝模型。已有两来源研究试检继续使用原来的共享编码器和统一参考文件。

入口：[公网产品接入页面](https://metalqc.online/#products) → 页面上方“产品族库”按钮 → “螺丝族”。

## 新数据的用途

使用 MVTec Screws V1.0，原始来源是 [MVTec](https://www.mvtec.com/research-teaching/datasets/mvtec-screws)，下载使用 [Neuromatch 教学页面](https://deeplearning.neuromatch.io/projects/ComputerVision/screws.html)明确引用的公开 OSF 镜像。许可 CC BY-NC-SA 4.0；原图和衍生裁图不随源码提交。

数据含 384 张图和 13 个类别。README 写 4,426 个标注，实际 JSON 有 4,427 条、标注 ID 无重复；按实际数据计数，不删一条数据来凑说明中的数字。

本阶段选取 9 类螺丝／螺栓，共 3,049 个候选零件；另外 4 类螺母不混入螺丝族。原始类别名为 type_001 等编号，网页中的中文名称是便于识别的外观别名，不代表厂家规格或已经确认的型号。

这些图片只有**类别和旋转框标注，没有正常／缺陷质量标签**。因此：

- 可用于外观覆盖整理、定位研发及参考候选筛选。
- 质量标签保持“来源未提供”。资料审核仅记录类别、裁剪、清晰度，不提供正常参考批准入口。
- 不产生新外观的缺陷准确率、召回率或自动归档资格。
- 当前质量试检模型仍只覆盖之前的 MVTec screw 和 M2 两来源／视图，新候选外观尚未参与其训练。

## 数据处理和隔离

1. 下载时核验 OSF 发布的 SHA256：`a742c5744cea973eca5d9eeee5896c8b458d3d695fb107a58707a9e7e0cc1342`。
2. 按原始旋转框裁剪、对齐，保留原图、框、类别和标注编号；以无损 PNG 保存候选图。**这依赖数据集标注框，不是自动定位已经完成。**
3. 按原始图片分组，比例约 70% 训练、15% 校准／验证、15% 测试。若不同原图含相同像素的裁图，先合并为同一分组再划分。
4. 保存源文件哈希、像素哈希、原始分区审计及当前分区清单。来源没有实物编号，不能保证同一实物的不同拍摄角度已完全隔离。
5. 外观审核结果独立存档，不赋予正常／缺陷标签，不加入正常参考库，也不改变数据分区。正常参考建设需要另外具有可信正常质量依据的数据。

实际分区如下。原始图的多件裁图都处于同一分区，当前没有重复裁图或同像素跨分区：

| 分区 | 原图数 | 螺丝候选数 | 用途 |
| --- | ---: | ---: | --- |
| 训练 | 269 | 2,132 | 外观识别、参考检索研发；不默认作为正常件 |
| 校准／验证 | 58 | 444 | 留出校准和验证，禁止加入参考 |
| 测试 | 57 | 473 | 封存评价，禁止加入参考 |

源数据的训练、验证和测试 JSON 会各自重编图像及标注 ID，审计原始分区时按文件名对应内容哈希，不把不同 JSON 中恰好相同的 ID 当成同一图片。原始发布分区按实际文件名检查也无重叠。

主要文件：`results/product_families/screw/appearance.json`、`mvtec_screws_v1/audit.json`、`appearance_checks.json` 和 `appearance_check_audit/`。原始数据在 `data/external/mvtec_screws/`。旧版 `appearance_reviews.json` 如已存在则保留审计，不再作为质量标签或正常参考批准依据。

## 需要用户做的第一步

先选择三类容易辨认的螺丝外观，每类抽查约 5 张，共约 15 张。这是资料抽查，不是缺陷检出实验，不需要专业检验员，也不要求逐张检查全部 3,049 张：

1. 在“外观资料审核（不判断质量）”里选一种外观，例如亮面螺丝、黑色螺丝或机螺丝。点击图片可查看裁图大图。
2. 只看三件事：是否属于显示类别，零件是否裁剪完整，图片是否足够清晰。
3. 填写审核人，勾选满足三项条件的图，点击“类别正确、裁剪清晰”；截断、严重遮挡、模糊或类别错误的图，填写备注后选“资料不适用”。拿不准的选“暂不确定”。
4. 若只是怀疑零件有损伤而没有质量依据，暂不确定即可，不给它编造正常或缺陷标签。
5. 每次操作保存独立审计记录。训练、校准／验证、测试图片均可做资料审核，但不会因此跨分区或进入正常参考库。

用户抽查用于发现资料整理问题。没有可信质量真值的这批图片，只能用于类别／匹配覆盖等外观任务评价，不能据此计算正常误报或缺陷召回。后续使用有质量真值的数据另行评价缺陷检测。

## 我负责的下一步

本轮三类审核已经完成，24张可用训练图已建立外观自动匹配试用入口；实验和边界见 [三类螺丝外观自动匹配实验](三类螺丝外观自动匹配实验_20261106.md)。这仍不向新外观赋予缺陷检测资格。

负责图像去重、整理、特征提取、外观自动匹配和按原图分组的留出实验；这批数据用于多外观识别与检索研发，不用它替代正常库。质量检测继续用已有可信质量标签的 MVTec AD 和 M2 数据，并寻找适合新增结构的质量数据。新外观缺少正常或缺陷真值时，明确保留质量验证缺口。继续研发无需标注框的单件定位，之后再验证多零件场景。

外观审核**不会修改质量标签、正常参考库、线上模型、阈值或自动归档策略**。旧浏览器即使仍发送“正常／缺陷”或“批准正常参考”请求，后端也会拒绝并要求刷新页面。
