# 人工复核与模型迭代

入口：启动本地服务后，进入工作台顶部的“人工复核”和“模型迭代”。

## 1. 最终核验

1. 在“人工复核”筛选产品、待复核/已复核/判定有误记录。
2. 打开一件样品，观察原图、热力图以及系统原始正常/缺陷判定。
3. 选择人工真实标签，填写复核人员、缺陷类型和核验依据。
4. 需要用于迭代时勾选“批准该最终标签用于离线迭代评估”，提交最终复核。

人工标签不覆盖原始判定。页面分别统计一致、误报和漏检；灰区“需复核”本身不被算作正确。复核人员属于本地操作员署名，不构成账号认证或数字签名。

每次修订保存在 `results/model_iterations/review_audit/`；当前标签保存在对应历史记录和 `results/feedback_candidates/`。再次复核并取消迭代授权，会从后续迭代输入中撤回该样本。

## 2. 生成候选

在“模型迭代”选择产品及以下一种方式：

- 模型重训：固定 CLIP 图像特征主干，使用原训练分区、正常训练参考和获准的人工复核训练样本，重新拟合正常/缺陷二分类判别头，再用校准分区选择门控阈值。
- 仅阈值校准：保持当前模型参数，使用冻结校准分区和新增独立复核校准图调整双阈值。没有独立复核校准样本时会说明原因并停止。

单个后台任务依次完成图像去重、分区检查、特征提取、训练/校准、导出一致性检查与回归评估。没有批准样本时不会启动。

## 3. 防止数据泄漏

- 图像按 RGB 像素内容识别，改文件名不会改变身份。
- 原公开数据集的冻结验证/测试图不能作为复核训练或调参样本回流。正常训练参考与评估图的内容重叠也会阻止评估。
- 新图按照产品和内容哈希确定用途：60% 训练、20% 校准、20% 新增审计。相同图片的用途保持一致，不允许在训练和评估分区之间重复。
- 原训练图可以由人工纠正标签；重复图不重复加权。同图的批准标签相互冲突时排除并提示。
- 缺图、复核后图片改变等情况会排除，候选详情中列出原因。

因此，批准样本数不等于实际训练样本数。数据不足、被排除或仅属于审计组时，任务会明确说明，而非伪造改善。

## 4. 对照与版本应用

评估页分别展示当前与候选版本在校准集、冻结回归集和可用新增审计组上的准确率、缺陷召回、误报、漏检、灰区占比与双阈值。

发布要求校准/冻结回归的准确率、平衡准确率和缺陷召回不下降；新增审计有相应指标时也不能下降。还需观察到校准指标改善，或者灰区占比下降且高风险误报不增加。未通过时保留当前版本。

上阈值在校准数据上要求高风险组至少 3 件、精确率至少 98%、正常件误报不超过 5%；没有满足区间时关闭高风险直出区。小样本结果不构成产线精度保证。

检验人员查看指标后点击“应用此候选版本”，模型参数和双阈值才成套生效。数据、标签、模型或线上配置在评估后变化，会阻止陈旧候选发布。当前检测批次未结束时也不能在网页切换版本。

已应用版本提供“回滚至发布前版本”。回滚只操作对应产品，并核验旧模型文件与当前版本状态，防止覆盖其他后续变更。

## 5. 报告与适用范围

当前结果、检验档案详情和人工复核详情均可导出 PDF。已复核报告包含真实标签、原始判定、一致性、复核人员、时间和依据；未复核报告明确标识待人工最终核验。

候选训练不会修改正常 patch 记忆库、微调 CLIP 主干，或自动训练多类别缺陷类型头。该版本闭环针对正常/缺陷判定和双阈值门控。

冻结回归集来自此前已观察的公开数据分区，属于回归检查，不是新产线盲测。持续评估同一分区会消耗其独立性；真实应用仍应逐步补充隔离的产线审计样本。
