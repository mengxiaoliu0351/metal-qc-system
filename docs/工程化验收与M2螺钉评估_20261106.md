# MetalQC 工程化验收与 M2 螺钉评估

更新日期：2026-11-06。公网入口：https://metalqc.online/ 。

## 1. 本轮交付与当前结论

已打通新产品登记、分区导入、独立建库、阈值校准、资格检查、接入检测、后台批次、来源标签核验回放、候选评估和发布否决。原螺母、螺丝、网格三个产品保留，新增 M2 螺钉头部俯视产品。

**新增 M2 产品可以检测，但当前版本的自动处置已暂停。** 封存测试发现自动误判，故转入复核；没有用测试集重新调阈值，也没有把待复核样本计作正确。原有三个产品的配置未因此替换。

这次交付证明流程能运行、能保存证据、能在效果不达标时阻止自动处置和发布，不代表产线认证或任意型号泛化。

## 3. 感知方案及封存结果

正常库方案只使用正常参考，校准阈值取 100 张正常校准图原始异常分数的第 99 百分位：0.2510126823。

标签增强方案使用冻结 CLIP 整图特征和 400 张有标签训练图拟合 Logistic Regression。局部正常库继续生成热力图。下阈值为 0.3614320788，上阈值为 0.8799911815。**它是可选的监督增强，不是零样本方法。** 网站接入仍保留正常库起步路径。

两个方案标签预算不同，下表用于说明冷启动和标签增强两条路径，不能归因于门控或 VLM。基线文件在本轮实验准备/执行期间固定，不宣称预注册实验；封存结果没有用于修改阈值。

| 指标，同一批 536 张 Test | 正常库方案 | 标签增强方案 |
| --- | ---: | ---: |
| 正确数 / 总数 | 341 / 536 | 491 / 536 |
| 准确率 | 63.62% | 91.60% |
| 缺陷召回率 | 35.13% | 89.96% |
| 正常件误报 | 14 / 257 | 17 / 257 |
| 缺陷漏检 | 181 / 279 | 28 / 279 |
| 混淆矩阵，行真实正常/缺陷，列预测正常/缺陷 | [[243,14],[181,98]] | [[240,17],[28,251]] |

标签增强提高了本次缺陷召回，但正常误报有所增加，仍不满足可靠自动放行的要求。

本地和云端各通过网站实际 API 跑完这 536 张，均 0 张任务失败，536 张二分类结果全部一致。最大模型分数差约 0.00000651。**两次是同一批图片的部署一致性验证，不能累加成 1,072 张独立测试样本。**

## 4. 为什么自动处置暂停

自动处置边界由校准集生成，自动正常线为 0.0565170217，自动隔离线为 0.9405701572。资格分区上 69 张落入自动正常、88 张落入自动隔离，未观察到相应错误，因此起初允许试验。

但资格分区通过没有保证封存测试也通过：

| 本地初次封存测试，暂停前 | 结果 |
| --- | ---: |
| 自动判断建议，含被抽查结果 | 383 / 536 |
| 被抽查 | 45 |
| 无需立即复核的自动结果 | 338 / 536，63.06% |
| 人工任务，含抽查 | 198 / 536 |
| 自动正常中的缺陷 | 6 |
| 自动隔离中的正常件 | 1 |

7 项自动错误导致该模型版本被否决。证据记录在 `results/release_evaluations/5bfef254b0b44900bfce16d8c2f34b8d.json`；暂停只针对相应产品与模型指纹，不清除历史结果，不改变真实标签。

云端部署带入同一暂停证据，因此后续 536 张全部转复核，自动完成为 0。这里“自动错误为 0”只是没有自动处置，**不能当作自动化准确率 100%**。检测分数、热力图和灰区分析仍可查看。

产品接入页同时显示建库时的资格检查和当前自动处置状态，避免把历史通过当成当前可用。

## 5. VLM 的实际作用

生产 VLM 仍为 `qwen3-vl-plus`。封存测试每次只有灰区的 39 / 536 张进入深度分析，39 张均成功返回，路径占比 7.28%。云端单图服务耗时中位数 1.483 秒，P95 为 5.864 秒；不含排队、导入和人工处理时间。

这不等于已证明相对全量 VLM 的时间或质量收益：本轮没有做相同样本的全量 VLM 对照；39 张灰区结果均保留复核，不能把分析成功当作标签判断正确。

先前 21 张回顾性 VLM 提示/模型对照发现增强提示仍把 5 张缺陷描述为正常，未满足放行条件，故未替换生产模型，增强模式默认关闭。详见 `results/experiments/vlm_focus_20261105/report.md`。

## 6. 核验与迭代的真实演练

预留核验分区中固定取 20 正常、20 缺陷。在本地和云端分别运行核验演示批次，再按发布方标签进行回放。记录注明 `dataset_label_replay`，不冒充真实检验员，不计入真实人工效率或日常作业统计。

40 张经像素哈希固定分成新增训练 23、校准 9、审计 8；训练与校准不使用 536 张封存 Test，也不使用 200 张冻结资格/回归图。

| 候选 | 校准缺陷召回：当前 → 候选 | 资格/回归缺陷召回：当前 → 候选 | 结论 |
| --- | --- | --- | --- |
| 判别头重训 | 96.26% → 95.33% | 100% → 99% | 拒绝发布 |
| 仅阈值校准，本地 | 96.26% → 94.39% | 100% → 98% | 拒绝发布 |

本地和云端重训结果一致。虽然候选灰区比例减少，但召回下降，系统阻止发布；线上未因此自动更新。已实际验证未通过候选的发布请求被拒绝。发布和回滚的成套性、数据/模型篡改防护有自动化回归覆盖；本轮没有强行发布失败候选来演练模型回滚。

结论是“闭环能评估并拒绝不合格更新”，不是“反馈后准确率必然提高”。当前还需要更有代表性的新增训练/校准图，以及未参与开发的新评估数据。

## 8. 网站上怎么使用

1. 打开公网紫色首页，进入完整工作台，选择左侧“产品接入”。
2. 查看 M2 产品的来源、各分区数量、建库报告和“当前自动处置已暂停”提示。
3. “运行封存测试”进入后台批次。相同配方和相同图片重复点击会返回已有任务，避免重复运行计费；536 张结果与来源标签对照在批次页查看。
4. “准备核验演示样本”创建/恢复 40 张预留样本批次；在人工复核中查看来源标签、记录核验并决定是否批准用于迭代。
5. 进入迭代评估，查看候选的校准、回归、新增审计结果和不能发布的原因。未通过不要应用。
6. 普通检测、批量任务和历史记录中均可打开原图、结果与 PDF；模型版本和作业处置与标签分开保存。

新接入自己的产品时，填写真实型号、视角、图片来源和许可；先上传正常参考与正常校准图走正常库路径。有明确缺陷标签时才启用监督增强；补足独立资格样本之前保持复核。不要把不同规格、视角和光照的数据无条件混为一个正常库。

## 10. 下一阶段优先事项

优先补充型号、视角和采集变化明确的数据，尤其是本轮漏检的缺陷形态；训练、校准与新的评估图按实物/采集批次隔离。先验证自动正常的漏检约束，再决定是否恢复该版本的自动处置。现有封存 Test 已用于观察和否决，后续重复只能称回归，不能重新包装为新盲测。

不以扩充页面数量、强行换大模型或反复调整测试集阈值作为改进成果。目前无真实检验员条件，因此保留来源标签回放的边界，先做好数据、可复现实验、错误处理和版本控制。
