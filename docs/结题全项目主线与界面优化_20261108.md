# 结题全项目主线与界面优化

## 项目要交付什么

面向金属表面图像检验的AI辅助作业系统。AI承担适用范围内的常规判断与按需分析，系统保存结果、分流例外与抽查，核验后的合格数据才用于受控迭代。目标覆盖速度、操作效率和质量追溯；当前没有真实产线节拍、人力分钟或认证效果证据。

从头梳理后，项目应围绕三个贡献陈述：

1. **把AI能力落成完整作业流程。** 选择产品、上传图片、检测、处置、复核、记录/PDF与候选评估可以衔接，公网可用。不是只显示模型分数。
2. **按需深度分析与选择性复核。** 本地处理明确结果，灰区调用VLM与RAG；版本权限、适用性、边界和抽查共同决定作业动作。没有用“转人工”冒充检测正确。
3. **统一产品入口并控制改进风险。** 用户选择“螺丝”后内部匹配视图；外观匹配与质量判别分离。数据按用途隔离、测试封存、候选评估和应用/回退分离。不是对任意型号通用检测。

## 设计为什么这样演进

最初以WinCLIP局部正常参考和双链路验证可行性；后续针对误判修复了正常库污染与模型兼容，并加入有标签整图判别，同时保留正常参考热图。因此当前方法应称“正常参考 + 标签增强 + 按需视觉分析”的应用集成，不能继续把整体称为纯零样本系统。

从“所有结果都人工确认”发展到“符合门槛的常规结果自动记录、例外与抽查复核”，体现减少人工负担的方向。但自动处置必须受权限约束：当前头部辅助评分全部复核；螺杆/新外观未通过质量门槛，不强套已有模型。软件隔离不是实体报废。

## 主报告保留与移出的内容

主报告保留问题、架构、代表性完整流程、AI与知识依据、复核迭代、三产品和螺丝族评估、交付与边界。头部536张改进只放备用页，供追问时展开。

逐轮螺杆失败调参、重复数据源统计、全部阈值数字、源码结构、旧方法名和逐条服务配置移出主讲页。它们保留在研发资料与原始报告中，不删除数据、不篡改失败记录。未证实的“国标原文页码”“人工节省比例”“行业权威认证”和“全型号高准确率”等表述不采用。

## 网站实际简化

- 日常导航突出工件检验、批次检验、人工复核、检验档案四项。
- 质效分析、模型迭代和研发设置放到可展开的“质量管理与研发”；旧链接仍可进入对应页面并展开导航。
- AI助手保留一个页面入口，去掉检测侧栏的重复助手标签；可携带当前图像/结果追问，返回后检测结果不丢失。
- 结果区优先呈现处置状态、原因和下一步；评分、阈值、匹配与分流技术依据默认折叠。复核与下一件按钮互斥，PDF仍可直接导出。
- 放大操作按钮、输入框、复核标签和表格文字；工作区改为中性工业配色，紫色首页保留。
- 复核页由七项并列统计简化为四项：待处理、其中抽查、已核验、已核验不一致。未改变保存标签、批准训练、模型或策略接口。

## 验收与限制

实际DOM运行检查覆盖页面启动、ID唯一、导航、研发展开、助手携带上下文及返回、自动与待复核两类动作、产品选择与文件清除；导航没有写请求。原选择器检查和4项后端HTTP契约测试通过。浏览器工具因无法可靠确认Edge当前URL停止；没有进行浏览器截图或宣称已做视觉验收。

前端五个静态文件已备份并同步现有公网，无重启；48个数据资产和4个后端文件校验未变。备份：`/opt/metalqc-backups/usability-20261108-final`。原评估源码、模型和策略冻结协议仍可复核。
